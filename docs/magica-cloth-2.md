# Magica Cloth 2 是怎么做的（调研，2026-10-02）

起因：骨骼布料调过一轮之后，用户看了 `out\g04_skirt_fix.mp4` 说"不行，还是有问题"，要先弄清楚 Magica Cloth 2（下称 Magica）本身是怎么实现的，
不再凭感觉调参数。

**结论先说：**

1. Magica 的骨骼布料（BoneCloth）和我们的 `RoeBoneCloth` 底子相同：骨骼当质点，按"基线"逐节做角度恢复、角度限制，加惯性、碰撞、背挡。
   参数的含义也基本一一对应（我们的插件本来就是照它的文档写的）。
2. 之前的猜测**核实了**：Magica 能把相邻的骨链横向连成网（连接方式 Automatic Mesh / Sequential Loop Mesh / Sequential Non Loop Mesh），
   横边上有距离约束、三角形之间有弯曲约束、横边也参加碰撞，一片裙子当一块布来算。我们只有 Line（每条链各自独立）。
   查了模型的蒙皮：**a08 每侧的长裙是一整片布，挂在前、侧、后 3 条链上；g04 的前片是一整片布，挂在 2 条链上**——我们把它们当成互不相干的绳子，
   视频里 g04 的前片下摆折起、卷边，就是两条链各摆各的。
3. 但这不是全部。Magica 文档对裙子的头号建议是**让"动画姿势"跟着腿走**：裙子蒙皮到腿上，或者美术逐个动作调好，模拟只是叠加在上面；
   做不到时用它的 Custom Skinning（把裙子自动蒙皮到指定的腿骨上）。游戏自己的技能动作正是美术手调的裙子。
   而我们动捕动作里的"动画姿势"是站架里的裙子钉在骨盆上：腿每迈一步都插进裙子，全靠碰撞把裙片推开，裙片就像硬板绕着腰转、被腿推着走。
4. 游戏本身**从不模拟裙子**：95 个 Magica 组件全在大厅模型上、全是 Line 模式、同一套头发模板（世界和局部惯性都是 0，质点限速 1 米/秒，非常稳）；
   战斗模型里一个都没有，裙子靠手调动画。所以照搬游戏的 Magica 设置解决不了裙子。
5. 建议：照 Magica 的做法改 `RoeBoneCloth`——裙子的动画姿势跟腿走（用游戏手调的裙子动画来标定）、一片布的几条链横向连起来、惯性分世界和局部。
   买 Magica（$17.50）能省掉第 2 条，但第 1 条照样要做；而且它挂在 Unity 的帧循环上按自己的时钟跑，我们离线录视频、跑检查时是手动一步一步推进的，
   它不会跟着动。详见第 8 节。用户选了 A，并要求可插拔、以后能换成 Magica：已做好，见第 9 节。

## 2. Magica 的结构

- **粒子 + 约束**，直接改位置的那类解法（PBD 式）。用 Unity DOTS（Burst 编译 + Job 多线程）写的，只用 CPU。
  公开的源码分析说积分是半隐式（leapfrog）。
- **固定频率**：默认每秒 90 步，和帧率无关；每帧最多 3 步，超出的跳过，用插值补位置。参数是在 90 Hz 下调的，
  手册说改了频率动作会变，要重调。
- **三种类型**：
  - BoneCloth：骨骼（Transform）就是顶点，模拟完写回骨骼的位置和旋转；
  - MeshCloth：从渲染网格简化出一个"代理网格"来模拟，再按距离权重带动原网格的顶点；
  - BoneSpring：给骨骼加弹簧（胸部）。
- **代理网格**：模拟的对象。BoneCloth 的顶点是骨骼本身：登记的根骨是**固定点**，下面的都是**可动点**。
  边：Line 模式只有父子边；网格模式另加横向边和三角形（见第 3 节）。
- **基线和深度**：从固定点沿着连接走到末端的路径叫基线，BoneCloth 的基线就是骨骼层级。每个顶点有深度（根 0、最远的末端 1）。
  带 [C] 按钮的参数都能用曲线按深度取值，比如角度限制在根部 12°、中间 36°、末端 60°。
  手册的说法是"沿基线恢复形状，得到一种 2.5D 的动作：既有二维动画式的动作，又保留物理感"。
- **两个基准姿势**：
  - 初始姿势：组件创建时记下的姿势；
  - 动画姿势：这一帧不用 Magica 时骨骼（或网格）被动画摆成的姿势。
  - `Animation Pose Ratio`（0–1，默认 0）在两者之间混合，影响角度恢复、角度限制、形状保持三项；**背挡和最大距离永远按动画姿势**。
  - 手册：一般留 0 更稳；动画姿势变形很大，或者"完全由美术控制"时，调高（从 0.5 试起）更稳。
- **写回旋转**（BoneCloth）：每根骨朝向相邻顶点。`Rotational Interpolation` 0 = 朝父、1 = 朝子（多个子取平均）；
  `Root Rotation` 决定固定的根骨朝子骨转多少。末端骨没有子，只能朝父。

### 各项约束

| 项目 | 做什么 | 参照什么 | 参数（取值范围；默认） |
|---|---|---|---|
| 重力、阻尼 | 重力；空气阻力 | — | 重力 0–10 米/秒²（5）；`Gravity Falloff`：布处在初始朝向时重力减弱；阻尼可按深度变（0.05） |
| 角度恢复 Angle Restoration | 每条基线边往原来的角度转回一部分；"最重要的参数，大部分动作由它决定" | 相对父边；基准 = 初始 / 动画姿势按比例混合 | 刚度（每次修正转回多少，可按深度变）；速度衰减（修正的位移有多少不变成速度，越低越像弹簧）；重力方向衰减（布朝上时恢复力减弱，重力为 0 也起作用） |
| 角度限制 Angle Limit | 每条边相对父边最多弯多少 | 同上 | 限制角（度，可按深度变）；刚度（越低越软地弹回） |
| 距离 Distance | 每个顶点和相连顶点保持距离（伸缩） | 原来的边长 | 刚度 0–1（1），可按深度变；手册：转圈的裙子可以把末端放松一点 |
| 系绳 Tether | 顶点离自己基线起点最多缩短多少，防止整片布塌缩 | 原来离起点的距离 | `Compression` 0–1（0 = 不许缩短；2.12 起默认 0.4）；手册建议不低于 0.8，太严动作会僵 |
| 三角弯曲 Triangle Bending | 相邻两个三角形的夹角回到原来的角度 | 原来的夹角 | 刚度 0–1（1）；没有三角形（Line 模式）就不起作用 |
| 惯性 Inertia | 角色的运动有多少传给布 | 见下 | 见下 |
| 最大距离 Max Distance | 顶点离动画姿势的位置不超过一个半径 | 动画姿势 | 半径，可按深度变；刚度 |
| 背挡 Backstop | 动画姿势顶点沿法线反方向的背后放一个球，顶点进不去 | 动画姿势 | 球半径 0.1–10；离顶点的距离（可按深度变）；刚度。BoneCloth 的法线默认是骨骼的 Y 轴，可改成从一个中心向外放射 |
| 碰撞 Collider Collision | 球、胶囊（两端半径可不同）、无限平面 | 碰撞体当前位置 | 模式：点（顶点当小球）/ 边（边当胶囊，不会从小碰撞体旁边漏过去，计算量是点的几倍）；半径可按深度变；摩擦 0–0.5 |
| 自碰撞 Self Collision | 布和自己、和另一块布不互穿（点对三角形 + 边对边） | — | 测试版，很费（文档标十颗星），要有三角形 |

### 惯性

- **三层**：锚点（比如角色站的移动平台，可以整个扣掉）→ 世界惯性 → 局部惯性。
- **世界惯性**：整个角色在世界里的移动和转动，从 MagicaCloth 组件所在的 Transform 量（所以要放在角色根下面）。
  - `World Inertia` 0–1：0.1 表示角色移动的 10% 传给布；
  - `World Movement / Rotation Speed Limit`：超过这个速度（米/秒、度/秒）的部分不再传给布，手册推荐用它而不是 `World Inertia`；
  - `World Inertia Smoothing`（2.12 起默认 0.4）：把角色的移动平滑一下，急起急停不打乱布。
- **局部惯性**：角色内部的动作（动画）对布的影响，从布的"中心"量：中心由固定点的分布自动算出（场景里那个紫色小球）。
  `Local Inertia` 0–1、局部移动 / 转动限速、`Depth Inertia`（靠近根部的顶点动得少，末端不减）。
- **其他**：离心力增强、**质点限速**（每个顶点的最大速度，低于 1 米/秒碰撞会不准）、瞬移检测（超过一定距离 / 角度就重置或保持）。
- 重置后有一段稳定时间（默认 0.1 秒），开始时布和碰撞体重叠也不会被一下子弹开。

## 3. 网格连接：一片布当一块布算（之前的猜测，已核实）

手册 "BoneCloth advanced settings" 原话：BoneCloth 可以从登记的骨骼自动建网格，"骨骼之间的连接更牢，形状保持和碰撞判定都更强；
横向也连成了边，配合边模式碰撞，碰撞还能更强"。手册用一圈 10 条链的裙子举例：

| 连接方式 | 怎么连 |
|---|---|
| Line（默认） | 只有父子边，各条链独立 |
| Automatic Mesh | 自动连附近的骨骼；骨骼排得不规则时形状可能不自然 |
| Sequential Loop Mesh | 按登记根骨的顺序横向连，首尾连成一圈（整圈的裙子） |
| Sequential Non Loop Mesh | 同上，首尾不连 |

连成网以后：横边有距离约束，三角形之间有弯曲约束，边模式碰撞把横边也算进去，还能开自碰撞。
一篇日文心得说得很直白：Line 模式左右不相连，腿会从链和链的缝里穿出去；换成 Automatic Mesh 腿就进不去了。

**我们的模型**（`magica_survey.py links`，看有没有三角面跨在两条链上）：

| 角色 | 一片布挂在几条链上 | 跨链三角面 / 两边都有权重的顶点 |
|---|---|---|
| a08 | 每侧长裙：前片 `Skirt_L_08` – 侧片 `Skirt_L_01` – 后片 `Skirt_L_16`（右侧是 `R_16`、`R_01`、`R_08`） | 80 + 20 / 260 + 245 |
| a08 | 后腰两条短片 `Skirt_M_00` – `Skirt_M_01` | 6 / 129 |
| g04 | 前片 `Skirt_front_007` – `Skirt_front_01` | 50 / 181 |
| g04 | 后片 `Skirt_Back`（宽约 26 厘米）、左侧长飘带 `Skirt_Left`（约 21 厘米）、装饰条 `Skirt_dec_Line`：各自一条链 | — |

图：`out\skirt_sheets_1002.png`（颜色 = 顶点挂在哪条链上，虚线 = 建议加的横向连接）。

g04 的后片和飘带各只有一条链，宽度方向本来就是一整块转，游戏里也一样；要它们在宽度方向弯，得像 MeshCloth 那样另建代理网格，游戏自己也没这样做，不需要。

## 4. 游戏自己怎么用 Magica

`magica_survey.py settings`：264 个大厅模型包里 95 个 MagicaCloth 组件，**全是 BoneCloth、全是 Line、几乎同一套参数**：

| 参数 | 游戏的值（95 个组件） |
|---|---|
| 重力、阻尼 | 5、0.05（全部） |
| 质点半径 | 1.5 厘米（68 个），其余 0.6–9 厘米 |
| 角度恢复 | 刚度 0（73 个）或 0.2（22 个），速度衰减 0.8 |
| 角度限制 | 90° × 深度曲线（根 0°、梢 90°）为主，少数 5° / 15° |
| 世界 / 局部惯性 | 0 / 0（全部） |
| 质点限速 | 1 米/秒（全部） |
| Tether、距离刚度 | 0、1 |
| 碰撞 | 点模式；没开背挡和最大距离 |
| 动画姿势比例 | 0 |
| 旋转 | 朝子骨 1、根骨旋转 1 |

- 模拟的是头发、刘海、耳饰、缎带、锁链；像布的只有几件：a08 裙上的两条锁链、a12 裙子两侧的两条链、几件头纱、披肩、k06 的斗篷。
- 战斗模型包（`chara_armor_*_hd & ld_hd.ab` 和 `_ld*.ab`）里没有 Magica 组件（抽查 a08、g04、a12、k06）：**战斗里全部是手调动画**，裙子也是
  （a08 以前在 ripper_tpose 的调研里查过，见那边的 `docs/bone-cloth-guide.md`）。
- 这套参数让头发几乎不受角色移动影响（惯性 0、限速 1 米/秒），大厅里很安静；拿来做格斗里的裙子没有参考价值。

## 5. 和 `RoeBoneCloth` 逐项对比

| 项目 | Magica Cloth 2 | RoeBoneCloth（现在） |
|---|---|---|
| 步长 | 固定 90 Hz，每帧最多 3 步，跳过的插值补 | 每步 1/60 秒拆成 2 个子步（120 Hz）；刚度按 90 Hz 换算 |
| 顶点 | 骨骼本身，根骨固定 | 每根骨的尾端（最后一节的尾端按蒙皮估） |
| 连接 | Line 或三种网格 | 只有 Line |
| 骨长 | 距离约束，可按深度放松 | 刚性，每次修正后投回骨长 |
| 横向距离、三角弯曲 | 网格模式有 | **没有** |
| Tether | 有 | **没有**（链可以往根部对折） |
| 角度恢复 | 相对父边；基准按比例混合初始 / 动画姿势；刚度曲线、速度衰减、重力方向衰减 | 相对父边；基准 = 动画姿势；刚度、速度衰减；每子步一次 |
| 角度限制 | 同上基准；按深度曲线；软限制（刚度） | 根到梢线性插值；硬限制 |
| 惯性 | 世界（角色根，平滑、限速）+ 局部（布的中心，深度惯性）+ 离心力 + 质点限速 + 瞬移检测 | 挂点骨（裙子是骨盆）一个比例 + 移动 / 转动限速 + 质点限速；世界移动和动画混在一起 |
| 碰撞 | 点 / 边（网格模式下横边也算）；半径按深度；摩擦 | 边模式（只有骨段）；动画本身压进碰撞体的深度放过；推开的位移九成不变成速度；杠杆和单次推量有上限 |
| 背挡 | 动画姿势顶点沿法线反方向的球 | 有，法线 = 从身体轴水平向外 |
| 最大距离 | 有 | 没有（插件里有，没移植） |
| 动画姿势 | 美术蒙皮或逐个动作调；或 Custom Skinning | 游戏动作：手调关键帧（不模拟）；动捕动作：站架的裙子跟着骨盆转，**不跟腿** |
| 重置后稳定 | 0.1 秒 | 没有 |
| 自碰撞 | 有（测试版） | 没有 |
| 写回旋转 | 朝父 / 朝子插值，根骨也转 | 动画朝向随父骨的偏转转过去，再摆到模拟方向（保留动画的扭转） |
| 地面 | 平面碰撞体 | 有 |

## 6. 为什么还不自然

对着 `out\g04_skirt_fix.mp4` 修改后那一半逐帧看（前进 2.0–2.4 秒、直拳 8.0–8.4 秒、回旋踢 9.6–10 秒）：

1. **一片布被拆成几根绳子**：g04 前片的两条链各摆各的，下摆折起、往一边卷；腿也能从两条链之间穿过去。a08 每侧三条链同理。
   → Magica 的网格连接正是解决这个的。
2. **动画姿势不跟腿**：动捕动作里，裙子的基准是站架里的样子钉在骨盆上（`FighterRig` 的根骨修正只让它跟骨盆、胯部朝向转）。
   迈步、踢腿时腿整个插进这个基准里，模拟只能靠碰撞往外推：裙片像硬板绕着腰转，被腿推着走，推完又被角度恢复拉回腿里。
   游戏手调的裙子是跟着腿走的：`RoeHelperFit.SkirtReport` 量过，g04 前片、侧片的根骨"钉在骨盆上"离游戏关键帧 27–28°，
   最好的"骨盆和大腿之间混合"也还差 20–23°（游戏的裙子本身摆幅 35–47°，大部分是摆动，靠模拟补）。
   → Magica 的答案是让动画姿势跟腿（美术蒙皮或 Custom Skinning），模拟叠加在上面，背挡、最大距离都相对这个姿势。
3. **惯性没分世界和局部**：前冲、后退、被击退时整个角色的移动和摆胯、迈腿算在同一个比例里，前后移动也会把裙子甩起来。
4. **没有 Tether**：链可以往根部对折（g04 前片卷边的另一半原因）。

## 7. 不用照搬的

- 游戏的头发模板（惯性 0、限速 1 米/秒）：大厅里安静是对的，格斗里裙子会像钉死的。
- 自碰撞：测试版、很费，我们的裙片之间很少互穿。
- MeshCloth：游戏自己的裙片就是一片一条链。
- 90 Hz：我们 120 Hz 子步、刚度按 90 Hz 换算，等价。

## 8. 改法建议（用户选了 A，做法见第 9 节）

**方案 A（推荐）：照 Magica 的做法改 `RoeBoneCloth`**，按影响从大到小：

1. **动捕动作里，裙子的动画姿势跟腿走**（Magica 的 Custom Skinning）：
   - `Init` 时取站架里每个裙子关节（每节骨的头、最后一节的尾）的位置，算它对骨盆、左右大腿、左右小腿的蒙皮权重；
   - 权重不只按距离猜，用游戏自己手调的裙子动画来标定：游戏全部自带动作里，裙子关节的位置 ≈ Σ 权重 × 骨骼的变换 × 站架里的相对位置，
     每个关节解一个非负最小二乘（`RoeHelperFit` 已经有在游戏动作上拟合的框架）；
   - 每步：动捕层下的裙子基准 = 蒙皮出的关节位置（方向由相邻关节定，扭转照站架）；游戏自己的动作仍用手调关键帧；
   - 角度恢复、角度限制、背挡以它为准，再加最大距离（离它太远就拉回来）；
   - 先量：游戏动作里，"钉在骨盆上"（现在）、"按距离蒙皮"、"标定的蒙皮"三种基准各离手调关键帧多远（一半动作标定、另一半检验）。
2. **一片布的几条链横向连起来**（BoneCloth 的网格连接）：
   - `Init` 时从蒙皮自动找：两条链之间有跨链三角面就是同一片布（a08 每侧 3 条、后腰 2 条；g04 前片 2 条），按深度逐层连横边，每格两个三角形；
   - 横边距离约束（裙摆处可以放松一点）、相邻三角形的弯曲约束、Tether；
   - 碰撞时横边也当胶囊，腿不会从两条链中间穿过去。
3. **惯性分开**：世界惯性按角色根（`Fighter` 的位置和朝向）算，带平滑和限速；局部惯性按骨盆相对角色根算，加深度惯性；重置后 0.1 秒稳定时间。
4. **检查**：`SkirtSwing` 的数字（摆幅、一帧最大跳动），新增"腿插进裙子多深（含横边）""横边伸缩多少""离基准多远"；
   `Skirt` 前、侧、后静帧；a08、g04 两个动作包的前后对比视频。

**方案 B：买 Magica Cloth 2（$17.50，用户自己买）**：
- 网格连接、Tether、分层惯性、Custom Skinning、自碰撞都是现成的；可以照第 3、4 节配：a08 每侧 Sequential Non Loop Mesh，Custom Skinning 到大腿和小腿，
  腿上胶囊用边模式，背挡法线从骨盆向外放射，参数从它自带的"Skirt"预设起调；
- 方案 A 第 1 条的事它也做不了更多：Custom Skinning 按距离蒙皮，手册自己说"只是替代办法，不太准"；
- 它挂在 Unity 的帧循环（PlayerLoop）上、按自己的 90 Hz 时钟跑，没有手动推进一步的接口。我们的 `RoeFightProbe`、`RoeClothDemo`、录比赛视频都是在批处理里手动推进的，
  布料不会跟着动，只能在播放模式里按真实时间录，数字检查就没了；
- 插件不能进仓库（`.gitignore` 已经排除 `Assets/MagicaCloth2`）。

## 9. 方案 A 做好了（10-02 晚）

用户选了 A，并且要"做成可插拔的方式，先用A，后续我想办法买到 Magica 再切换"。

**可插拔**：
- `IRoeCloth`（`Runtime/RoeCloth.cs`）：布料后端的接口——动画求值前 `Rest()`，姿势算完后 `Step()`，`Reset()`，混合权重 `Weight`。
- `RoeClothBackends`：后端列表，游戏里按 **F4** 依次切换（比赛重新开始，计时下方显示 `CLOTH: ...`）：
  - `magica_style`：照 Magica 做法的骨骼布料（默认）；
  - `legacy`：10-02 那一版，留着对照；
  - `off`：不模拟，裙子和头发照站架的关键帧；
  - `magica`：Magica Cloth 2 本身。草稿已写好（`Runtime/RoeMagicaCloth.cs`，照手册的运行时构建接口）：同样的分片（连成网的链 → Sequential Non Loop Mesh，其余 Line）、同样的参数、同样的腿部胶囊（MagicaCapsuleCollider）、`animationPoseRatio = 1`（恢复到我们算的"跟腿走"的姿势）。
    要等插件装上、在 Player 设置的 Scripting Define Symbols 里手动加上 `ROE_MAGICA` 才参与编译——没装插件时不影响工程。
    注意：Magica 挂在 Unity 的帧循环上按自己的 90 Hz 时钟跑，游戏和 exe 里会动；编辑器批处理里的检查和录视频是手动一步步推进的，它不会动。

**1. 动捕时裙子的动画姿势跟腿走**（`Runtime/RoeSkirtRig.cs`、`RoeHelperFit.FitSkirt`）：
- 6 个驱动：胯部朝向（只有水平朝向，相当于"垂着"）、骨盆、左右大腿、左右小腿。每节裙骨尾端的位置 = 各驱动从站姿把它带到哪里的加权平均（线性混合蒙皮，权重 ≥ 0、和为 1）。
- 权重用游戏自己手调的裙子动画拟合：idle_01、react_01、skill_01、skill_03、hurt 拟合，没参与拟合的 idle_02、react_02、skill_02 上检验。
  每节骨的方向偏离游戏关键帧多少（RMS，度）：

  | | 钉在骨盆上（原来） | 按距离蒙皮（Magica 的 Custom Skinning） | 拟合 |
  |---|---|---|---|
  | a08（32 节） | 35.5 | 33.0 | **31.1** |
  | g04（34 节） | 47.2 | 38.7 | **37.2** |

  剩下的误差大部分是美术加的摆动（游戏的裙子本身摆幅 35–47°），这部分交给模拟。拟合出的权重有规律：靠腰的骨跟骨盆，
  下摆跟同侧小腿，g04 的后片几乎全跟"胯部朝向"（垂着），前片中间的两条链一半跟一侧大腿、一半跟另一侧小腿。
- 运行时：驱动的基准是动捕站架（`Init` 里按真实的每步流程走一圈站架取平均，含着地和踩实脚的 IK），裙子的基准是游戏站姿里的裙子（相对胯部朝向）。
  站架时和原来完全一样；腿离开站架，权重在腿上的骨就跟着走。每节骨只摆不扭，从"蒙皮出的头"指向"蒙皮出的尾"。
  坑：链的第一节如果从它在骨盆上的真实位置指过去，g04 整片裙子在站架里就偏了 2 厘米（游戏站姿的骨盆是歪的，动捕的是正的，头的位置不一样）；
  改成从"骨盆带着的站姿头部位置"指过去。
- 基准姿势插进腿多深（腿部胶囊、扣掉站姿里本来就有的，平均厘米；游戏自己的技能动作量出来平均 0.5–3）：

  | | 站架 | 前进 | 后退 | 跑 | 刺拳 | 挥砍 | 直拳 | 踢 |
  |---|---|---|---|---|---|---|---|---|
  | g04 钉在骨盆 | 0.5 | 5.8 | 4.7 | 6.2 | 0.7 | 6.3 | 4.1 | 2.8 |
  | g04 跟腿走 | 0.5 | 5.3 | 4.3 | 5.2 | 0.4 | 4.5 | 2.3 | 1.9 |
  | a08 钉在骨盆 | 3.7 | 3.9 | 3.8 | 3.8 | 5.0 | 5.4 | 5.0 | 5.7 |
  | a08 跟腿走 | 3.7 | 3.4 | 3.5 | 3.5 | 4.4 | 5.1 | 4.2 | 4.6 |

**2. 一片布连成网**（`RoeBoneCloth.Link`）：
- 从蒙皮自动找：同一组骨链里，有 6 个以上三角面跨在两条链上（顶点按"哪条链上的权重加起来最多"归属），就是同一片布。
  a08 每侧前、侧、后 3 条链各连 4 层，后腰两条短片；g04 前片两条链连 6 层。
- 横边：保持动画姿势里的距离；横边也当胶囊去碰腿，腿不会从两条链中间穿过去。
- 坑：打包出来的游戏里，游戏的网格没开 Read/Write，读三角面会报 "Not allowed to access triangles"，一条横边都找不到
  （编辑器里没这个限制，检查和视频都正常）。改成从 `BakeMesh` 的副本读三角面；骨骼权重本来就读得到，所以腿部胶囊的粗细一直是量对的。
  打包后跑一下 exe 看 `%USERPROFILE%\AppData\LocalLow\ROE Fighter\ROE Fighter\Player.log` 里有没有 `linked`。

**3. 其他几项**：
- 惯性分两层：世界惯性按角色根（`Fighter` 的位置、朝向），裙子 0.15、限速 1 米/秒和 120°/秒；局部惯性按骨盆相对角色根，0.3，深度惯性 0.3（靠腰处感觉得少）。头发、链子、胸照原来的数值分到两层，表现基本不变。
- Tether 0.15（离链根不近于动画姿势的 85%），最大距离从根部 3 厘米到末端 25 厘米（离动画姿势），重置后 0.1 秒稳定。
- 碰撞放行：原来是"动画姿势插进腿多深就放过多深"，钉在骨盆上的基准插得很深，腿就这么穿过去了；现在只放过站姿里本来就有的深度。

**结果**（`RoeFightProbe.SkirtSwing`：一个角色在真实的格斗逻辑里依次站架、前进、后退、侧步、四个攻击；每段动作取裙子插进腿部胶囊最深的一刻，
下面是各段的平均，括号里是最深，厘米。胶囊按皮肤的 70% 分位数量，比腿略粗，所以这不等于看得见的穿模深度，只用来比较）：

| g04，Bandai 包 | 7.5（9.1） | **2.2**（5.8） | 0.8 / 2.5 / 1.6 / 1.0 / 0.9 / 3.9 / 5.8 / 1.0 |
| g04，ACCAD 包 | 6.8（9.6） | **1.8**（3.4） | 0.6 / 1.9 / 1.8 / 0.7 / 0.6 / 2.9 / 3.4 / 2.9 |
| a08，Bandai 包 | 6.9（8.5） | **4.6**（7.1） | 3.7 / 4.7 / 4.3 / 4.1 / 4.0 / 4.5 / 7.1 / 4.5 |

- a08 站架就有 3.7：游戏站姿和动捕站架的腿位置不一样，按游戏站姿垂下的裙子在动捕站架里本来就挨着腿。
- 一帧里裙摆最大的跳动差不多（旧 15–28°，新 19–22°）；裙摆偏离动画姿势的平均角度大了 1–2°（基准跟着腿动、碰撞真的在推）。
